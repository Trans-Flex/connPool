# Go TCP Connection Pool

一个用于 TCP 长连接管理的轻量级连接池，可作为底层组件集成到 HTTP 代理或中间件中。

## 核心特性

- **并发安全**：使用 `sync.Mutex` 配合带缓冲的 `chan` 实现，通过 `go test -race` 检测。
- **限制控制**：
  - `MaxIdle`：通道容量，控制最大空闲连接数。超过此数量的归还连接会被直接 Close。
  - `MaxActive`：全局最大连接数限制（活跃 + 空闲）。达到上限时，后续的 `Get` 请求会阻塞排队。
- **假死连接检测**：在 `Get` 时，对拿到的连接进行 1 毫秒的读超时探测。超时说明连接存活；报错或读到数据说明连接已损坏或脏数据，直接销毁并重试。
- **最小化锁粒度**：仅在修改 `totalConns` 状态时加锁，发起 `net.Dial` 等耗时操作时不持有锁。

## 核心 API

- `NewConnPool(maxIdle int) *ConnPool`：初始化连接池。
- `Get() (net.Conn, error)`：获取连接。若池子空且未达上限则新建；若达上限则阻塞等待。
- `Put(conn net.Conn)`：归还连接。若空闲通道已满则直接关闭该连接。

## 测试

项目包含并发压测用例。运行以下命令：
```bash
go test -race -v
```
当前测试覆盖了 10 个并发协程争抢 4 个连接上限的场景，确保假死检测、名额控制与阻塞唤醒逻辑无误。

## 后续优化
